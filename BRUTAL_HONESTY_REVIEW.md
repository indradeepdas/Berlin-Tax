# Brutal Honesty Review

Review date: 2026-05-08

This repository should be judged by whether it reduces unsafe certainty, not by how impressive its scaffolding looks.

## What Still Feels Weak

- The project is early and should not be marketed as a complete bureaucracy system.
- Examples are useful fixtures, not evidence that real workflows are solved.
- Accountant handoff drafts are only useful when source documents and evidence state are attached.
- UStVA support is calendar and readiness oriented, not filing-figure preparation.
- Cross-border, ALG I, immigration, payroll, and UG/GmbH cases remain review-heavy.

## What Would Reduce Trust

- Any `pass` status for a case with missing source documents.
- Any workflow that hides professional-review items inside friendly prose.
- Any source-backed value copied into docs without config metadata.
- Any public fixture containing fake full addresses, fake tax numbers that look real, or fake authority acceptance.
- Any contributor claiming legal or tax certainty from an LLM response.

## Maintainer Response

- Keep the README explicit about current maturity.
- Keep examples fictional, redacted, and visibly incomplete when appropriate.
- Prefer deterministic `review` or `fail` over optimistic `pass`.
- Require source governance and stale-rule review for every unstable rule.
- Add more validators before adding more broad workflows.
